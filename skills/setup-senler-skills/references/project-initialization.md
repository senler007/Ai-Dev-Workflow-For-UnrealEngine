# 初始化内容

这是新项目各文件的正文组织方法。路径、职责与维护规则以同级安装的 `project-documentation` 为准；这里只提供实际写入内容，不重新定义文档体系。

根据已确认输入生成简体中文正文，不把下面的说明原样当成项目事实。没有内容的可选段落直接省略，不输出尖括号变量、TODO 或空表格。所有项目引用从目标项目根目录解析。

## AGENTS.md：项目工作规则

标题使用真实项目名。可直接采用下面的通用规则，并仅补充本项目已确认的约束：

- 先查同类功能并复用完整公共流程；不新增无需求功能，不把局部实现差异扩大为新架构。
- 新功能或行为变更先使用 `$grilling`，由 `$ask-plan-build` 承接结论并给出具体方案，用户确认后实施。需求已清楚时整理结论，不凑问题；已有答案和批准继续有效。明确的小范围修改和已批准方案直接执行。
- 逻辑改动交付前使用 `$code-review`；稳定行为或维护入口改变时使用 `$project-documentation`，同步受影响的现有文档。
- Unreal 任务使用 `$unreal-project`，具体项目工具与命令仅填写实际已配置的入口。非 UE 项目省略这一条和 UE 专用配置。
- 使用已安装的全局 Skill；不要求在项目内复制一套。若项目已有明确的本地 Skill 来源声明，保留并据实标明当前来源，不擅自改写为已迁移。
- 项目文档必须遵循 `project-documentation` 规定的固定路径和职责。正文用简体中文，文件名、命令和代码标识保持原样。一项事实只维护一处。
- 模块的设计、架构和维护入口合放 `Docs/Modules/<功能名>.md`；新建模块指南须有明确需求或批准，不建空占位、每日记录或独立架构文档。
- 验证覆盖实际改动和受影响的原功能，按风险选择必要的运行视角。清楚区分已检查内容和剩余验证，不把编译成功当作功能验收。
- 只有实际共享工作区或编辑器才协调写入冲突；跨会话消息和外部服务操作遵循当前用户授权，不导入其他项目的授权。
- 不自动提交、推送、创建 Tracker 工单或定时任务。

加入按任务读取的文档导航表，指向固定的概览、术语、README 和实际模块。规则属于 AGENTS.md；不要在 README 再维护一份开发流程。

## README.md：如何使用和维护仓库

使用真实项目名作为标题，并链接概览。写明：

- 已存在的工程入口、所需环境，以及已确认的运行方法；实际版本来自当前工程或用户提供信息。
- 实际已有的源码、资源和内容根目录及命名约定，不猜测尚未建立的资源目录。
- “资产版本与临时备份”章节：保留未提交和未保存成果；备份按明确项目约定处理，不默认复制整套资产；冲突和恢复规则由相应 Skill 负责。

如果目标确实是空目录，本次仅建立文档，则明确记录“当前只有项目文档，尚未创建可运行工程”，不要编造启动命令。没有源码或内容目录时列出本次实际创建的文档入口即可，不建空的源码/资源目录。

## CONTEXT.md：共同词汇

优先记录用户已确认的项目专有术语及其含义，不发明游戏设定。
如果尚无业务专有词汇，至少明确已经采用的三项工作流含义：

- 核心体验：项目希望用户获得的主要体验；具体内容由项目概览维护。
- 模块：可独立理解的一组功能职责，其设计和维护入口合放对应模块指南。
- 验收：对照已确认需求检查实际结果；编译成功不等于功能完成。

这些是已采用的约定，不是待填占位。以后出现项目专有术语时在此维护。

## Docs/ProjectOverview.md：项目概览

写入真实项目名称、简短用途、用户已确认的核心体验，以及实际已有文档的导航。作为项目定位的唯一权威入口，README 只链接它。

从概览链接根目录文档时使用相对当前文件的正确路径：`../AGENTS.md`、`../README.md`、`../CONTEXT.md`。可选的世界观、模块和外部参考只有实际存在时才链接。用户没有提供 Figma 文件时，省略外部参考段落，不复制其他项目链接。

## 可选文档

- 有已确认世界观内容时，在 `Docs/Worldbuilding.md` 整理世界观与角色事实，概览补充导航。
- 有真实模块且本次已经获准建立指南时，在 `Docs/Modules/<功能名>.md` 写其效果、职责、关键实现和资源入口、修改位置及稳定验证方式。不要根据远期规划批量创建模块文档。
