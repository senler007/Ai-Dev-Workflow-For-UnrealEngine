# 2026-08-19

## 目标

- 把反复修不好 Bug 时的证据驱动方法沉淀为一个可隐式启用的修复 Skill。
- 整合全部 10 个 Skill，通过 3 个独立 Agent 交叉评审优化工作流、授权边界、验证与可维护性。

## 实际实现

- 新增支持型 `$fix-bug`，建立可复现的红色信号、最小化场景、可证伪假设、第一个错误状态定位、回归测试、敏感信息脱敏和诊断清理契约；取消未经批准的固定尝试次数和自动提交含义。
- 打通 `$implement → $code-review → commit` 闭环：以起始 `HEAD`、初始 patch 和未跟踪文件快照识别任务增量，统一审查已提交、已暂存、未暂存和未跟踪内容；同文件 hunk 无法安全拆分时保留工作树并报告。
- 审查统一优先读取调用方传入的 Spec、Tickets 或 Bug 验收契约，在 Standards、Spec、Documentation 三个独立轴内标注 blocking/advisory，修复范围内阻断问题后复测并复审。
- 统一所有消费方的 setup 授权与配置路径发现：缺少配置时只提示用户显式运行 `$setup-senler-skills`；新增 GitLab 一等 Tracker 配置，补齐本地 Tracker 的 Parent、Status、Ready/Done 字段契约。
- `$grilling` 同步为决策树与 frontier rounds，同时保留 Senler 不使用子 Agent 的差异；`$tdd` 复用已确认 seam，并要求红色测试因预期行为而失败。
- `$project-documentation` 将完整文档角色和模块结构规则交由现有 references 单一维护，并同步更新中英文 Skill 清单。
- 仓库契约测试扩展到 43 项，覆盖全部 Skill 的 frontmatter、metadata、跨 Skill 引用、递归 Markdown 链接、双语 README 清单与关键工作流契约。
- 验证：10/10 Skill 在 `PYTHONUTF8=1` 下通过 bundled `quick_validate.py`；43/43 项仓库测试与 `git diff --check` 通过。
