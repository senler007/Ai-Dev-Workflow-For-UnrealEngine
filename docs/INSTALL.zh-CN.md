# 整套 Skill：安装与新项目接入

## 1. 全局安装

准备 Node.js/npm 和 Git，在 PowerShell、终端或 Codex 终端执行：

```bash
npx --yes skills add senler007/skills --skill '*' --agent codex --global --copy --yes
```

这条命令从本仓库默认分支下载全部 12 个 Skill 及其引用文件、脚本，
使用 [Vercel Skills CLI](https://github.com/vercel-labs/skills) 安装到 Codex 的全局技能目录。
实际路径以命令输出为准。`--skill '*'` 选择全部包，`--agent codex` 只配置 Codex，
`--global` 对所有项目可用，`--copy` 避免 Windows 符号链接要求，`--yes` 跳过安装选择。

它会更新同名安装；如果你有自己修改的版本，先保留副本。
已有项目级同名 Skill 不会与全局版自动合并，初始化时核对实际使用的来源。
不要把项目路径、账户授权或运行账本放进公共 Skill。

重启 Codex 后检查 `$setup-senler-skills` 等是否可用。
Skill 发现机制见 [OpenAI 文档](https://learn.chatgpt.com/docs/build-skills)。

## 2. 初始化每个项目

在 Codex 打开真实项目目录，发送：

```text
使用 $setup-senler-skills 初始化当前项目，使用已经安装的全局 Skill。
检查并复用已有资料，建立或合并项目文档、文档导航和开发流程。
```

补充 AI 无法从文件判断的项目定位、核心体验等信息即可。
初始化使用项目自己的语言、引擎版本、目录和工具；已有文档更新相关段落。
文档职责表见 [中文 README](../README.zh-CN.md#新项目怎么用)。

没有世界观或术语内容时不用凑出对应文件；不默认添加开发日志、空模块指南或独立架构文档。
已有 Tracker 则沿用，没有则先以当前需求与批准方案作为范围来源。
初始化可重复运行，不应重复插入段落、重置决策或覆盖已有项目定制。

## 3. 开始新功能

```text
使用 $grilling，给当前项目增加保存并切换角色外观方案的功能。
```

先查项目事实，再澄清会改变结果的决策；之后 `ask-plan-build` 直接承接已有答案，
给出具体文件、行为与验证方案。批准后实施，按风险验证，审查改动并更新变化的文档。
明确的小改动和已有批准不重复问答。所有技能都已安装，无需为这些阶段继续下载。

## 4. Figma 任务管家的首次配置

完整包已包含管家与其伴随工作流。运行管家还需要：

- 已连接的 Figma 插件，包括 `figma-use` 与目标文件访问权。
- Codex 桌面端提供项目、独立会话、会话消息工具。
- Python 3.8+，用于包内的 `scripts/ledger.py`（仅依赖标准库）。
- 项目概览中记录真实 Figma 文件与任务页（默认「每日安排」）。

配置好入口后可以发送：

```text
使用 $figma-task-steward 管理当前项目的 Figma 任务页。
允许为交给 AI 的任务创建独立会话，并在这些参与会话之间发送派发、交接和完成消息。
允许在任务卡上写回简短进度，保留原需求和人工内容。
先核对已有会话与任务归属。静态调查可以并行，共享项目的写入、构建和编辑器操作串行。
```

有了这次明确授权，后续在相同范围内沿用，不逐次重问。
需要每日自动创建新管家时，另外说明自己的时间和时区；安装本身不会创建自动任务，
管家也不是实时监听器。不能用作者的旧授权替代自己的首次启用。

账本位于个人 Codex 目录下的 `figma-task-steward/<工作区路径哈希>/state.json`，
由随包脚本管理版本与原子写入。它不在 Skill 安装目录里，不随更新删除。
它协调参与工作流的会话，不是操作系统锁；不同电脑、独立检出目录无需争同一把锁。
详细协议见 [管家 Skill](../skills/figma-task-steward/SKILL.md)。

## 5. UE 项目与更新

`unreal-project` 已随整套安装。初始化会使用项目实际 UE 版本、内容目录与约定，
资产操作仍需要已配置且可用的 UE 编辑器集成；缺失时报告具体受限操作。

更新全部 Skill：重新执行第一步的命令。已有项目文档保持原样，
需要采用新版路由规则时，再在该项目运行 `$setup-senler-skills`。
不要删除运行账本，也不要用作者项目的文档覆盖自己的事实。
